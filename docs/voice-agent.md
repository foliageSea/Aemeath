# 爱弥斯语音助手使用说明

## 运行结构

```text
ESP32 双麦克风 → ES7210 → 16k PCM + 本地 AEC → /voice → 电脑本地 KWS + VAD
                                                        ↓ 唤醒后问题
                                    MiMo ASR → Eino / OpenAI兼容 LLM
                                                        ↓ 回复文字
ESP32 扬声器 ← ES8311 ← 16k PCM ← MiMo 分句 WAV / Fish 双向音频流
      └── LVGL 爱弥斯 Q 版形象随会话状态变化
```

上图为设备模式：电脑主动连接 ESP32，原 `/ws` 性能与额度通道独立运行。独立模式无需 ESP32，改为“系统默认麦克风 → 电脑本地 KWS/VAD → MiMo ASR → LLM → MiMo/Fish TTS → 系统默认扬声器”，不执行设备发现或连接。独立模式仍依赖云端 ASR、配置的 LLM 与 TTS 服务，不能离线完成语音对话。

两种模式的默认唤醒词均为**你好小爱**，可在“设置 → 语音 → 离线唤醒”的“唤醒词”中修改。采用电脑离线识别，不调用云端 ASR 识别待机音频；只有唤醒后的一轮问题发往 MiMo。对话期间持续进行离线唤醒检测（电脑本地播放期间暂停）：录音、识别、思考、合成或设备扬声器播放时再次说出已保存的唤醒词，会停止旧轮请求和播放并立即开始新一轮倾听，可直接连说“唤醒词 + 新问题”，无需再唤醒一次；最多补回关键词结束后 2 秒的音频。触屏和桌面端也可取消；静音或离线唤醒未就绪时使用按钮取消。未启用免唤醒连续聊天。

## 1. 安装资源

桌面应用中打开“设置 → 语音 → 离线唤醒”，在“离线唤醒模型”卡片点击“安装唤醒模型”即可下载安装中文唤醒与 Silero VAD 模型（约 33 MB），无需终端。界面会显示下载进度，支持取消和失败后重试；已安装的模型仅做本地校验，不重复下载。模型目录默认收在“模型目录与高级选项”中，安装使用当前选定的目录。已有文件校验失败时不会覆盖，请检查文件或更换一个尚不存在的目录。

安装不会自动保存其他设置。若安装目录正用于当前已启用的语音连接，安装成功后会重连并加载模型；修改了目录时，保存设置后生效。唤醒模型不包含参考音频；需要默认参考 WAV 或完整命令行安装时，在仓库根目录执行：

```bash
cd agent
go run ./cmd/aemeath-voice-assets
go run ./cmd/aemeath-voice-assets -verify
```

安装命令显式联网下载固定版本的中文关键词模型、Silero VAD 和参考 WAV；每个文件校验编译进程序的 SHA-256，拒绝不符的内容，不修改桌面设置。日常启动和 `-verify` 不下载。受损目录不会被静默替换，可以用 `-dir /新的绝对路径` 重新安装；随后在桌面语音页设置模型目录 `<dir>/models`、参考音频 `<dir>/reference.wav`。

默认目录是 `os.UserCacheDir()/Aemeath/voice`：macOS 通常为 `~/Library/Caches/Aemeath/voice`，Windows 通常为 `%LOCALAPPDATA%/Aemeath/voice`。留空的配置路径会使用默认值。

离线关键词使用 `sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01`，官方 sherpa-onnx Go/native 版本 2.0.1，按已保存的唤醒词自动生成拼音关键词，无需手写拼音或重新下载模型。唤醒词会去掉首尾空白；留空使用“你好小爱”，自定义词支持 2–12 个模型支持的中文汉字，不支持标点、数字、拉丁字母或词内空格。多音字采用拼音库的默认读音，可能与预期不同，建议换用读音明确的词并实际试唤醒。依赖原生 cgo；无 cgo 的监控版会明确显示离线唤醒不可用，不会偷偷改用云端待机识别。

## 2. 更新固件

本节仅适用于 ESP32 设备模式；独立模式跳过固件与设备配网。

```bash
. ~/.espressif/v6.0.2/esp-idf/export.sh
cd firmware
idf.py build
# 确认串口确实对应这块开发板，再执行烧录：
idf.py -p /dev/cu.usbmodem11101 flash monitor
```

新的语音通道需要新固件；旧固件不具备音频能力，不能只更新桌面端。代码会协商版本与 PCM 格式，握手失败时显示语音连接错误。首次 Wi-Fi 配网方式及长按 BOOT 清除 Wi-Fi 的行为不变。

板载 I²C 使用 GPIO47/48；I²S MCLK5、BCLK16、LRCLK7、DOUT6、DIN15，功放由 TCA9554 EXIO3 控制。ES7210 两路麦克风以 16 kHz/16-bit 标准双槽采集后下混，ES8311 在同一时钟格式输出。右槽仍是第二路麦克风，不作为 AEC 参考。固件使用 ESP-SR 2.6.1 的全双工 AEC（FD_HIGH_PERF、NORMAL 残余回声抑制）：从 TX DMA 完成回调保存实际播放 PCM（含软件音量、功放开关和欠载静音），按共享时钟的 TX/RX 帧序号与麦克风配对，经过回声消除后再上传。AEC 的 32ms 原生帧会重新分成协议要求的 20ms 帧；配对交付额外等待一帧，播放期间持续采集。取消、清空和静音走独立控制队列，播放启动异步等待 DMA 清空。回声抑制与用户同时讲话的保留效果仍需在实际设备、音量和距离下验证。

## 3. 桌面配置

在 MyGO 桌面应用打开“设置”。顶部“助手”Tab 位于“屏幕”和“语音”之间，包含“基础设置、对话服务”两组，分别配置启用状态与角色设定，以及 LLM、上下文、Agent 工具和 Tavily；“语音”Tab 保留“语音识别、语音合成、离线唤醒、声音试听”四组（也可从“语音助手”页点击“语音设置”进入）。智能家居位于独立的“智能家居”Tab。左侧选择分组，右侧显示对应表单；切换分组保留草稿和各组滚动位置，顶部“保存设置”统一保存所有 Tab 的修改：

无需 ESP32 时，先在“设置 → 连接 → 运行模式”选择“独立模式”并保存；默认麦克风与扬声器由操作系统选择，可在系统声音设置中调整。已有 ESP32 的用户可保留“设备模式”。

1. 在“助手 → 基础设置”开启语音助手、设置角色偏好，再在“对话服务”填写 OpenAI 兼容 API 的 Base URL、模型与 API Key。Base URL 通常以 `/v1` 结尾；接本地无鉴权兼容服务时可以留空 LLM Key。
2. 在“对话服务”默认开启“自动读取模型上下文容量”，并填写“备用上下文容量（Tokens）”。JSON 的 `contextWindowMode` 默认 `auto`，仅支持 `auto` / `manual`；关闭开关使用手动模式，数值标签改为“手动上下文容量（Tokens）”。`contextWindow` 在自动模式中是备用值，在手动模式中是上限，0 或省略默认 32768（32K），手填范围 8192–2097152。保存设置后会重新连接并应用模式和数值。若启用工具，所选模型必须支持 tool calling；不支持时关闭工具模式使用纯对话。
3. 切换到“语音”Tab，在“语音识别”填写 MiMo API Key；此组的地址和密钥也供 MiMo 语音合成使用。在“语音合成”选择 MiMo/Fish 并配置音色、参考音频。默认 MiMo Base URL 为 `https://api.xiaomimimo.com/v1`；它与文字 LLM 可以使用完全不同的服务商。
4. 在“离线唤醒”填写“唤醒词”，留空使用默认“你好小爱”。资源安装在默认位置时，无需改动模型、参考音频路径。默认音量为 70，0 是有意静音。灵敏度对应关键词阈值，越低越容易触发，也可能增加误唤醒；推荐先保持 0.25 并实测。
5. 点击顶部“保存设置”，然后在“声音试听”调整音量。先“播放参考音频”检查当前模式的扬声器，再“试听语音”检查合成服务，最后测试唤醒和完整对话。

设置先保存才生效，刷新不会覆盖未保存表单。修改唤醒词后点击顶部“保存设置”，现有配置更新机制会重启当前模式的音频会话（设备模式重新连接设备，独立模式重新打开本机音频）并加载新词，无需退出重开桌面应用；当前对话可能中断。语音助手页的唤醒提示使用已保存的词，未保存的草稿不会改变提示。API Key 只保存在电脑的现有私有设置文件中，权限 `0600`（Windows 实际访问控制仍由用户目录 ACL 决定）；界面遮罩，错误日志不输出 Key。不要把包含 Key 的设置文件提交到 Git 或分享。

未安装 KWS/VAD 时显示“离线唤醒未就绪”；仍可手动唤醒和试听用于排障。缺少 VAD 的手动录音采用明确提示的 6 秒固定窗口，不代表自动唤醒已经就绪。

### 网络代理

打开“设置 → 连接 → 网络代理”，选择以下三种模式。旧设置未指定模式时也使用“系统”：

| 界面 / CLI 值 | 行为 |
| --- | --- |
| 系统 / `system` | 默认。优先使用代理环境变量，再读取 macOS / Windows 的手动系统代理设置；没有适用代理时直连。 |
| 代理 / `proxy` | 只使用手动填写的代理 URL，支持 `http://`、`https://`、`socks5://`，需包含主机与端口，例如 `http://127.0.0.1:7890`。代理连接失败或认证失败会报错，**绝不回退直连**。 |
| 直连 / `direct` | 忽略代理环境变量和系统代理，直接连接目标。 |

系统模式按请求协议选择 `HTTP_PROXY` / `HTTPS_PROXY`（也支持对应小写名称），`NO_PROXY` / `no_proxy` 的绕过规则同样适用于系统手动代理。该协议未配置环境代理时才读取系统设置；macOS / Windows 系统设置最多缓存 5 秒，其他平台仅使用环境变量。手动“代理”模式不读取这些环境代理规则，只保留下文的本地目标直连例外。代理 URL 不应带路径、查询参数或片段，例如不要在端口后追加 `/`。

仅“代理”模式显示 URL 输入。URL 可能包含用户名和密码，因此默认遮罩，可点击眼睛按钮显示 / 隐藏；不要分享包含认证信息的截图、配置或终端历史。切换到“系统”或“直连”会保留未启用的 URL 草稿，不会用它连接。修改模式或 URL 后点击顶部“保存设置”才应用，并重新连接当前语音会话，可能中断当前对话；普通快照刷新和切换页面不会覆盖未保存的草稿。资源安装、试听与其他后台请求使用已保存的代理配置，而非未保存的输入。

代理适用于云端 LLM、MiMo/Fish、Tavily、公共目录与语音资源下载等网络请求；本地目标 `localhost`、回环 / 私有 / 链路本地 **IP 字面量**、`.local` 地址自动绕过代理。**ESP32 设备连接与 Home Assistant MCP 始终直连**，即使填写公网地址也不走代理。此设置只控制 Aemeath 自身，不更改系统代理或进程环境。

**不支持 PAC / WPAD 自动代理，也不执行自动配置脚本。** 系统只有自动代理、没有适用的环境变量或手动代理时，请求会明确报错，不会悄悄直连；请改用手动“代理”或明确选择“直连”。

Agent 和资源安装 CLI 均支持 `--proxy-mode`（默认 `system`）及 `--proxy-url`，启动时校验参数。CLI 不读取或修改桌面已保存的代理设置；在 `agent` 目录运行：

```bash
# 云端服务走本机 HTTP 代理，ESP32 / HA 仍直连
CGO_ENABLED=1 go run ./cmd/aemeath-agent --standalone --voice-config voice.local.json \
  --proxy-mode proxy --proxy-url http://127.0.0.1:7890
# 资源下载使用 SOCKS5 代理
go run ./cmd/aemeath-voice-assets --proxy-mode proxy --proxy-url socks5://127.0.0.1:7890
# 明确忽略环境变量和系统代理
CGO_ENABLED=1 go run ./cmd/aemeath-agent --standalone --proxy-mode direct
```

### 按住快捷键说话

Aemeath 启动后注册 **F8 全局快捷键**：无论当前打开哪个页面、正在使用其他应用，还是已关闭窗口驻留托盘，都可以按住 **F8**，对着当前模式的麦克风说话（设备模式：**ESP32 设备麦克风**；独立模式：**系统默认麦克风**）；松开 F8 后，录音通过现有 MiMo ASR 识别并直接发送给 Agent，随后按当前模式的有效播放位置播报回复。部分 Mac 键盘需按住 **Fn + F8** 才会发送 F8。若 F8 已被占用，自动改用 **Ctrl + Shift + F8**（Mac 上是 Control，不是 Command）；“语音助手”页会显示实际生效的快捷键，下文的 F8 操作对应这个已显示的组合。应用退出后释放快捷键。若两个组合均注册失败，“语音助手”页会显示错误；关闭冲突应用后可重新保存快捷键设置以重试。

在 **设置 → 助手 → 基础设置 → 触发快捷键** 输入组合键名称，点击顶部“保存设置”后立即生效并持久保存。例如 `F9`、`Ctrl+Shift+Space` 或 `Cmd+Shift+A`。支持 F1–F24（macOS 最高 F20）、A–Z、0–9、Space；字母、数字和 Space 必须至少搭配 Ctrl、Alt 或 Super，不能只加 Shift。修饰键支持 Ctrl / Control、Shift、Alt / Option、Super / Cmd / Command / Meta / Win，忽略大小写及各部分两端空白；Super 在 macOS 表示 Command，在 Windows 表示 Win。macOS 字母数字按 US ANSI 物理键位映射；系统保留组合仍可能注册失败。

- 自定义组合先注册验证，保存成功后才释放旧组合并切换；格式错误、占用冲突、保存失败时保留旧快捷键和修改草稿。切换成功会取消当前按住录音，避免旧键松开后误发；仅修改快捷键不重连语音会话。
- 留空，或点击“恢复默认快捷键”后保存，恢复 F8 → Ctrl+Shift+F8 自动选择。显式配置的组合注册失败时不会悄悄改用其他键；启动失败状态和当前生效组合会显示在界面。
- 桌面设置 JSON 的顶层字段为 `voiceShortcut`，如 `"voiceShortcut": "Ctrl+Shift+Space"`；留空/省略沿用默认自动选择，与 CLI 的语音配置无关。

- 需要启用语音助手，且当前模式的音频会话已就绪；设备模式要求连接设备语音通道。无需先说唤醒词，也不要求离线唤醒模型就绪。
- 按住期间停顿不会提前结束录音，单次最长 30 秒；到达上限会自动结束并识别。
- 切换页面、切到其他应用或关闭窗口驻留托盘时，录音会持续到松开 F8。Aemeath 窗口在前台时可按 **Esc** 或点击“取消对话”丢弃尚未提交的录音；退出应用也会丢弃录音。Esc 不注册为全局快捷键。
- 按下 F8 会打断当前对话或播报并开始新一轮录音。设备麦克风静音时无法开始录音。
- 原有“手动唤醒”按钮仍按自动断句方式工作；缺少 VAD 时该按钮采用 6 秒固定窗口，F8 按住录音由松键控制结束。

### 文本输入

在“语音助手”页底部输入文字，按 **Enter** 或点击“发送”发起对话，**Shift + Enter** 换行。文字跳过语音识别，直接使用现有 Agent、上下文、工具与所选播放位置的语音回复，记录会显示在同一对话列表中。发送文字会打断当前录音或播报并开启新一轮。

需要启用助手并让当前模式的音频会话就绪（设备模式需连接设备语音通道）；无需离线唤醒模型，设备麦克风静音时也可发送文字。空白消息不会发送，单条最多 4096 UTF-8 字节；未连接时可先编辑草稿。发送失败会保留输入，发送期间继续编辑的新草稿也会保留。

### 对话语音重播

助手回复下方的“重播”可再次播放该条回复**已生成的原始音频**，同时支持 MiMo 分句合成和 Fish 流式合成。重播不重新调用 ASR、LLM 或 TTS，不重复执行工具，不新增对话、修改上下文或增加模型用量；播放位置和音量沿用当前音频会话的有效设置。

- 完整语音生成后即可重播；点击会停止当前录音、生成或播放，从选中回复的开头播放。重播期间该回复下方显示“停止”，也可使用原有取消按钮、F8、手动唤醒或发送新消息打断。电脑播放期间仍暂停自动唤醒。
- 无缓存时，按钮显示“合成播放”及简短的“可能收费”提示；悬停或点击信息按钮可查看完整说明。点击后按**当前已保存的音色**仅调用 TTS，可能产生语音合成费用；不会重新调用 ASR、LLM、执行工具或新增对话与模型用量。恢复的历史文字、旧连接或被淘汰缓存的回复均可重新合成。成功生成的完整语音会进入缓存，下次优先复用；同样的回复文字也可复用当前连接的音频。重合成过程中可点击“停止”取消；失败不会自动重复付费重试。单条回复最多 **16384 UTF-8 字节**，实时回复尚未完成时暂不可重新合成。
- 音频仅缓存在本次语音连接的内存中，最多保留最近 **10 条**完整回复，合计不超过 **5 分钟**；单条沿用 **120 秒**限制，超过总量时优先淘汰最早的回复。尚未完整生成、合成失败或被提前取消的音频不进入缓存，可在回复结束后手动重新合成。
- “清空对话”会同时删除音频缓存。保存设置导致的语音重连、设备断线重连或退出应用后，旧缓存不可恢复；历史文字仍按原有规则保留。未缓存或已过期的回复可通过上述按钮显式重新合成，**不会在后台自动付费合成**。声音试听与参考音频不进入对话重播缓存。

### 播放位置

在“设置 → 语音 → 声音试听”选择“Agent”（当前电脑的系统默认扬声器）或“监控台”（ESP32 设备扬声器），点击“保存设置”后生效。设备模式的输入仍使用 ESP32 麦克风，切换输出不解除设备语音通道的连接要求。独立模式固定使用系统默认麦克风和扬声器，“播放位置”显示本机有效输出并禁用；即使原先保存为“监控台”（JSON `playbackOutput: "agent"`），运行时也自动按“Agent”播放，不覆盖已保存的设备模式偏好或 CLI 配置文件。试听与正常回复使用同一有效输出；电脑音频不可用会明确报错。

本机播放没有 AEC（声学回声消除），自动唤醒在本地音频播放期间暂停，播完恢复，避免把扬声器回复识别为新问题；不能在此期间依赖喊唤醒词打断。F8 按住录音、手动唤醒、取消和发送文字仍可中断当前轮次。CLI 使用对应的 `record_start`、`wake`、`cancel`、`text` 命令。此限制也适用于设备模式选择“Agent”输出。

### 系统音频与权限

独立模式使用系统默认输入/输出，无需 ESP32、本地网络发现权限或固件升级。macOS 首次启动本机录音会请求麦克风权限；桌面安装包与 CLI 的 darwin+cgo 构建均包含用途声明，普通 `go run` / `go build` 无需额外链接参数。在“系统设置 → 隐私与安全性 → 麦克风”允许 Aemeath，CLI 则允许启动程序的 Terminal、iTerm 或其他终端宿主。Windows 在“设置 → 隐私和安全性 → 麦克风”开启“麦克风访问”和“允许桌面应用访问麦克风”（Windows 10 的入口为“设置 → 隐私 → 麦克风”）。麦克风拒绝授权、没有默认输入设备或无法打开音频设备时，会报告错误，修复权限/系统默认设备后重启音频会话。扬声器在系统声音设置中选择；蓝牙切换等设备变化后可重启会话重新打开默认设备。本机音频需要带 cgo/原生音频支持的构建，关闭 cgo 的监控构建不具备此能力。

### 智能家居：Home Assistant MCP

桌面 Agent 从本机通过 Streamable HTTP 连接 Home Assistant（HA）官方 MCP Server；运行桌面的电脑必须能访问 HA，接入 HA 无需更改 ESP32 固件。HA MCP 默认关闭，需要同时在“助手 → 对话服务”启用“启用 Agent 工具”，对话模型支持 tool calling 后才能在语音对话中调用。

1. 在 Home Assistant 中启用 **Model Context Protocol Server** 集成，并选择允许 Assist 暴露的实体，具体步骤见 [HA 官方 MCP Server 文档](https://www.home-assistant.io/integrations/mcp_server/)。
2. 复制集成提供的 **Device control** 地址，默认是 `http://homeassistant.local:8123/api/mcp/assist`；将主机名替换为桌面能访问的 HA 地址。
3. 在 HA 的个人资料（Profile）中创建长期访问令牌（Long-Lived Access Token），复制到桌面“设置 → 智能家居”的“长期访问令牌”。首版手动填写令牌，通过 `Authorization: Bearer <token>` 请求头认证，没有浏览器 OAuth 登录流程。
4. 在“智能家居”开启“启用 HA MCP”，填写“服务地址”和令牌。令牌默认遮罩，可用眼睛按钮显示/隐藏；点击“测试连接与刷新工具清单”检查连接和当前可用工具，然后点击顶部“保存设置”。
5. 保存并确认 Agent 工具已开启后，可以说“你好小爱，打开客厅灯”或“你好小爱，客厅温度是多少？”。可操作设备取决于 HA 实际返回的工具和权限。

默认 Device control 地址使用 HA 的 Assist 暴露实体范围。也允许填写完整 `/api/mcp` 地址或自定义工具集 URL；这些地址的可访问工具、实体和权限以 HA 服务端实际配置及令牌权限为准，不能假定仍受 Assist 暴露列表限制。

工具从 HA 动态发现，在模型中使用 `ha_` 名称前缀。每轮对话刷新工具清单，新增或移除的工具会随之更新；HA 离线或发现失败不会阻断现有的七个 Agent 工具，下一轮对话或再次点击测试可重连。发现预算为 8 秒，单次工具调用预算为 20 秒；取消对话或更短的父请求期限会提前终止。客户端不会自动重放 `tools/call` 动作。HA 工具沿用现有语音对话的执行过程和结果卡片，显示标题、状态、耗时、参数及结果。

HA 配置与其他语音设置一起持久化到本机私有设置文件。令牌只用于桌面到 HA 的认证，不发送给 LLM，不放在 URL、工具结果或日志中；不要分享含令牌的配置副本。

## 4. 命令行

参考配置为 [voice.example.json](../agent/voice.example.json)，示例使用 `"contextWindowMode": "auto"` 和 `"contextWindow": 32768`；后者是自动读取失败时的备用值。标准接口不一定提供容量，自动失败不阻断对话；改成 `"manual"` 可始终使用手填上限。创建自己的私有副本，填写模型；密钥推荐从环境传入。`voice.local.json` 已加入忽略规则。

```bash
cd agent
# 复制示例并编辑你自己的 voice.local.json，避免提交真实 Key。
export AEMEATH_LLM_API_KEY="你的文字模型 Key"
export AEMEATH_LLM_MODEL="你的模型名"
export MIMO_API_KEY="你的 MiMo Key"
CGO_ENABLED=1 go run ./cmd/aemeath-agent -voice-config voice.local.json -addr aemeath.local:80
```

无需 ESP32 的 CLI 独立模式：

```bash
CGO_ENABLED=1 go run ./cmd/aemeath-agent --standalone --voice-config voice.local.json
# 所有配置从环境提供时，无需 --voice 或 JSON：
CGO_ENABLED=1 go run ./cmd/aemeath-agent --standalone
```

`--standalone` 自动启用语音，跳过 mDNS 发现与设备连接，不能与 `--addr`（包括空地址）或 `--dry-run` 同用。CLI 启动日志明确显示独立模式、系统默认麦克风/扬声器及实际播放位置 `console`（界面名称“Agent”，电脑扬声器）；运行时自动覆盖旧配置中的 `agent`（界面名称“监控台”，ESP32）输出，不写回 JSON。进程仍在本地更新性能指标和 Magpie 额度供 Agent 工具使用；`set_page` / `set_screen` 返回明确的设备不可用错误，本机锁屏等工具按既有规则运行。

设备模式也可仅用 `-voice` 启用并从环境提供模型参数；无 `--standalone`、`-voice` 和 `-voice-config` 时保留原监控行为。支持环境变量：

| 环境变量 | 含义 |
| --- | --- |
| `AEMEATH_LLM_BASE_URL` | 文字模型兼容 API 根地址 |
| `AEMEATH_LLM_API_KEY` | 文字模型密钥，覆盖 JSON |
| `AEMEATH_LLM_MODEL` | 文字模型名 |
| `MIMO_BASE_URL` | MiMo 根地址 |
| `MIMO_API_KEY` | MiMo 密钥，覆盖 JSON |
| `TAVILY_API_KEY` | Tavily 网页搜索密钥，覆盖 JSON 的 `tavilyAPIKey` |
| `HA_MCP_ENABLED` | `true` / `false`，覆盖 JSON 的 `haMCPEnabled`（默认 `false`） |
| `HA_MCP_URL` | HA MCP Streamable HTTP 地址，覆盖 JSON 的 `haMCPURL`；默认 `http://homeassistant.local:8123/api/mcp/assist` |
| `HA_ACCESS_TOKEN` | HA 用户长期访问令牌，覆盖 JSON 的 `haAccessToken`（默认空） |

终端中输入 `wake` 手动唤醒、`record_start` 开始手动录音、`record_stop` 结束并识别提交、`record_cancel` 丢弃未提交的录音、`text 你的问题` 直接文字对话、`cancel` 取消、`clear` 清空上下文、`preview 你好，我是爱弥斯。` 合成试听、`reference` 播放参考音频；每条命令按回车提交。手动录音最长 30 秒，CLI 不注册桌面 F8 快捷键。Ctrl+C 取消请求、停止并等待语音 worker 退出，随后释放本机音频。设备模式下，桌面版与 CLI 不要同时占用同一台设备；设备音频通道只允许一个拥有者。

## 5. 对话与动画

内置爱弥斯设定包含人物背景、性格、称呼与朗读习惯，资料依据和改编示例见[角色设定说明](aemeath-persona.md)。角色设定留空使用内置版本；已保存的非空设定继续优先使用，升级后可清空并保存以采用新版。

- 说“你好，小爱”后角色页立即挥手；随后播放聆听 `waiting`、识别/推理 `review`、合成/播报 `running`，错误 `failed`，完成 `idle`。
- 可连续说“你好，小爱，帮我看看 CPU”；2 秒预缓冲按关键词末端截取，识别文字中的句首唤醒词会被剔除。如果识别到的只有唤醒词，会正常提示“我在听，请继续说出问题”并重新聆听一次；5 秒内没有问题则回到待命，不作为故障。对话期间离线再次命中唤醒词时会取消旧轮并开启新录音（本地扬声器播放期间暂停自动唤醒，需手动打断）；新录音仅在检测到问题并完成断句后提交云端。只说唤醒词而没有后续问题时，等待超时后回到待命。未被离线检测截掉、但 ASR 结果仍仅含唤醒词时，使用上述最多一次的继续聆听逻辑。模型对齐点并非精确音素边界，应在实际说话速度下验证是否截掉首字。
- 约 800 ms 尾部静音提交问题，5 秒无问题退出，最长一轮录音 30 秒。识别、Agent、合成分别最多等待 60、90、180 秒，取消随时生效；播放音频最多 120 秒。合成单独计时，不再被较早阶段耗时或旧的 60 秒 HTTP 总超时截断。
- LLM 最终正文采用流式接收。桌面正文随有效文字增量独立更新，不等待 TTS 分段；语音状态通过通知触发约 50 ms 窗口的合并刷新，指标与托盘仍每秒刷新。临时正文快照使用独立的最新值通道，不受 PCM 缓冲背压阻塞；设备侧正文消息限频，最终全文始终发送。MiMo 首个完整短句即可开始合成，后续按较大的句组顺序合成，每轮最多 8 段；Fish 使用独立的短句/短时缓冲策略，不受 8 段上限限制。整轮合成共用从首批文字开始计时的 180 秒预算，总音频仍最多 120 秒。需要兼容 API 支持 SSE 流式聊天；流失败不会自动重放工具或整轮请求。
- 音频真正开始输出后才显示说话，播放能量驱动声波；不能把网络收到音频误作扬声器已经播放完成。桌面“语音助手”在每轮对话的“执行过程”中显示工具名称、执行中/完成/失败/取消状态与执行耗时，可展开查看参数和结果摘要；工具事件不会进入回复正文或语音合成。对应轮次同时保留识别、思考、合成累计耗时及首段播放耗时，底部操作栏显示当前轮已合成与已播放段数及进度。生成与播放并行时，总段数仍可能增加，进度以当前已合成段数为基准；播放完成计数以设备实际回执为准。首段耗时从提交识别音频起计，结束于设备首次实际 `playing` 回执，不包含录音等待。
- 结束后角色页停留 3 秒再恢复原页面。临时亮屏不覆盖持久亮度设置；手动切页或屏幕操作优先于自动恢复。
- 上下文按 Token 预算管理，自动模式仅查询显式启用的 models.dev 公共目录，未启用、未匹配或无可用缓存时立即使用备用容量，不阻断对话。不向对话服务查询上下文容量，不调用 `/models/{id}` 或 `/models` 元数据接口。目录容量允许 4096–2097152 Tokens，不代表已验证的真实可用上限；不按模型名猜值、不用 usage 反推容量。自动模式备用值和手动上限默认 32768（32K），可在“设置 → 助手 → 对话服务”配置。输入预算从模型容量中扣除了回复、安全余量与工具增长等预留开销；目录如有独立 `limit.input`，输入预算和工具增长硬限制还会受其约束。占用为按序列化请求估算的值，不是服务商精确分词或计费数据。达到输入预算的 70% 后台提炼摘要，85% 在下次请求前同步压缩；摘要后优先保留最近 4 轮完整问答，硬预算不足时可进一步裁剪完整问答，摘要失败时可回退裁剪旧对话。当前单轮工具结果过大时安全报错，不自动重放工具。
- 桌面操作区默认以紧凑状态栏显示上下文估算占用比例、进度条、容量和重要摘要状态；未初始化时显示“等待初始化”，不显示虚假的零占用。点击“详情”展开 Tokens / 输入预算、容量来源、摘要 Tokens、保留/压缩/丢弃轮数和“累计用量”；容量用 K 简写，精确 Tokens 数与请求模型 ID 可在容量悬浮提示中查看。容量来源显示“models.dev / 手动设置 / 使用备用值”。占用达到 85% 或摘要压缩失败时突出警示，窄窗口允许状态换行。桌面每秒从共享记忆读取统计，后台摘要无需新对话事件也能更新，刷新保留展开状态。累计用量始终显示输入/输出/总计 **Tokens（本地估算）**；启动后立即回显上次保存的累计值，无需新语音事件，无保存用量时从 0 开始。按实际发送的请求（含历史上下文、工具定义和工具结果）及收到的输出（含可见推理和工具调用）在本地估算，覆盖工具决策、回复与摘要请求，非精确分词，不等于服务商计费用量；UI 不展示服务商上报的 usage。每次请求被接受计入输入和响应结束计入输出后即保存，不等待一轮对话结束；闲置、重连、重启后继续累计，自动压缩或预算裁剪不会清零。本地累计仅在手动清空对话时归零，并删除保存记录。
- 完成的文字问答、摘要及压缩/丢弃次数会以私有权限保存在设置旁的 `voice_history.json` 文件中，跨闲置、设备重连和应用重启持续保留并恢复，不因闲置时长自动过期；仍按 Token 预算自动压缩或裁剪，本地累计用量不受影响。文件仍使用 version 2，新增 `local_usage` 字段，例如 `"local_usage": {"input_tokens": 12000, "output_tokens": 700}`；启动恢复输入 12000、输出 700，总计按两项相加得到 12700，旧文件缺少此字段时本地累计为 0。服务商上报的 usage 不持久化，UI 只读取本地累计字段。已配置模型时，桌面启动后立即根据当前角色设定、内置工具和恢复的历史重算上下文估算占用，同时回显保存的累计用量，无需先发起对话或联网；使用已启用的目录缓存或备用容量估算，不等待服务商初始化或容量查询。手动“清空对话”删除记忆、摘要及保存文件，同时清零本地累计用量。历史录音不保留。

### models.dev 公共目录

在“设置 → 助手 → 对话服务”保持自动读取开启，再开启“使用 models.dev 查询上下文容量”。默认关闭，手动容量模式不使用或下载目录。JSON 对应字段：

```json
{
  "contextWindowMode": "auto",
  "modelsDevEnabled": true,
  "modelsDevProvider": "openai",
  "modelsDevModel": "gpt-4o-2024-05-13"
}
```

- 两个映射字段留空时，按目录服务商的 API 根地址和完整模型 ID 精确匹配；原生 SDK 服务商不一定记录 API 地址，内置识别 OpenAI 官方根地址，其他未匹配服务可手动填写服务商 ID。
- 中转地址、部署别名需指定目录服务商 ID，模型 ID 留空则使用实际请求模型 ID；填写目录模型 ID 可显式映射别名。映射只用于本地容量查询，不改变对话请求的模型或服务地址。不做跨服务商名称搜索、模糊匹配、去前缀或去版本号；歧义或未知条目继续使用备用值。
- 固定下载 `https://models.dev/api.json`，只读取 `limit.context` 与可选的 `limit.input`，不把输出上限当作上下文容量。目录数据只表示该条目公开的限制，中转站或私有部署可能提供更小的容量，必要时改用手动上限。
- 后台下载最多 5 秒、最多 32 MiB，不跟随重定向，不携带服务商认证或模型查询参数。模型匹配在本地完成，不发送密钥、对话、请求模型 ID 或自定义服务地址。
- 桌面在设置旁保存 `models_dev_cache.json`；CLI 在系统用户缓存目录 `Aemeath/models_dev_cache.json` 保存。缓存只保留公共服务地址、模型 ID 和容量字段，原子写入、仅当前用户可读写；不与对话记忆混存。
- 优先读取缓存，24 小时后可后台更新；桌面每 5 分钟检查是否需要刷新，下载失败至少间隔 5 分钟重试并继续使用旧缓存。CLI 在连接及需要目录的对话时检查刷新。首次无缓存时不等待目录，直接使用备用容量，目录就绪后最迟在下一轮对话采用，期间不会改变正在进行的请求预算。
- 来源明确显示为“models.dev”，悬浮可查看目录条目与独立输入上限。关闭目录开关后不再发起目录更新，已缓存文件保留；手动模式始终使用手填容量。

### Agent 工具

内置 Agent 工具包括 `get_metrics`、`get_quota`、`set_page`、`set_screen`、`lock_computer` 和 `web_search`；不包含任意 shell 或文件执行。在“设置 → 助手 → 对话服务”启用“启用 Agent 工具”并保存后，可以说“你好小爱，帮我锁屏”或“锁定这台电脑”。`lock_computer` 无参数，作用于运行 Agent 的电脑当前登录会话；`set_screen` 仍控制 ESP32 监控台屏幕。锁屏工具仅在用户明确要求电脑锁屏时使用，返回结构化的请求提交成功/失败结果，不把请求提交当作已验证最终锁屏状态。macOS 使用系统原生锁屏接口（旧系统可用 CGSession），Windows 使用 LockWorkStation；其他平台明确返回不支持。开启工具时先用独立的短工具选择请求完成 ReAct 工具调用，再以禁止工具的流式请求生成最终正文；选择过程、推理内容和工具参数不会朗读。这会比无工具模式多一次选择请求；无工具模式直接使用单次 SSE。切页协议没有设备页面 ACK，工具会说明指令已发送，而非声称已确认切页。

网页搜索可直接说“你好小爱，帮我上网搜索 ESP32-S3 的官方文档”。`web_search` 接受 `query`（最多 256 个字符）和可选 `limit`（默认 3，最多 5）；使用 Tavily Search API，需在“设置 → 助手 → 对话服务”填写“Tavily API 密钥”并保存；CLI 可在 JSON 配置 `tavilyAPIKey` 或设置 `TAVILY_API_KEY`（环境变量优先）。单次最多等待 12 秒，固定使用 basic 搜索深度，不请求 Tavily 生成答案或返回网页原文。模型得到网页标题、摘要和 URL，界面工具卡片可展开查看并打开来源，回答可用 [1] 等编号对应来源。搜索只读取摘要，不抓取网页全文；外部资料不作为指令执行，失败或无结果会明确返回，取消对话会取消搜索。搜索词会发送给 Tavily；请求使用 Bearer 鉴权，密钥不放在 URL 或结果中，不自动切换其他搜索源。未配置密钥只影响网页搜索，每轮时间快照和设备工具仍可用；鉴权失败、请求过频和额度不足会分别提示。Tavily 的额度与计费以账户方案为准。

每轮用户请求都会在系统上下文注入一份本地时间快照，包含日期时间、时区名称与 UTC 偏移、中文星期、UTC 时间，并标明来源为电脑系统时钟、未进行外部校时；无需联网，关闭 Agent 工具也生效。普通“现在几点”“今天星期几”和今年/明天等相对日期问题直接使用快照，不再要求先查时间工具。同一轮的工具决策、工具续接和最终回复共用同一采样时刻，下一轮重新采样；快照计入上下文预算，但不作为消息写入持久化历史。时区名称若为 `Local`，同时给出时区缩写与明确的 UTC 偏移，不将其猜成某个 IANA 地区。

已移除独立的 `get_current_time` 工具及其调用提示，模型无法再调用它，也不再请求外部时间服务。时间问题使用本轮系统时间快照，不为确认当前时间额外搜索；下一轮自动更新快照。历史对话中的时间结果卡片仍可查看。

## 6. MiMo 和参考音频

ASR 保持为 `mimo-v2.5-asr`。TTS 可在桌面设置选择 MiMo 或 Fish；默认仍是 MiMo，模型为 `mimo-v2.5-tts-voiceclone`。两者使用 `/chat/completions`，不是 `/audio/speech` 或 `/audio/transcriptions`。克隆合成将目标文字放 assistant 消息，参考 WAV 转 Base64 data URL 放 `audio.voice`。不上传网页地址，不需要虚构“训练音色 ID”。

**此 voiceclone 模型目前不是低延迟逐块生成。**每个句组仍使用 `stream:false` 接收完整 WAV，随后转换成 16 kHz PCM 发给设备；首段无需等待全文或后续句组生成完成。分段会增加合成请求数、重复发送参考音频的量和可能的计费开销，后续句组因此合并得更大，并限制最多 8 段。试听/重试已生成文字的入口仍为单段合成，不重新运行 LLM。等待时角色展示合成动画；不对首包延迟作实时承诺。若请求超时或响应中断，界面显示具体阶段、错误类别和实际耗时。已经获得文字回复时，可点“重试回复语音”只重新合成这条文字；不会重复运行 Agent 工具，也不会自动重发可能已经计费的请求。

默认素材来自用户提供的[爱弥斯 Wiki](https://wiki.kurobbs.com/mc/item/1457744312692867072?wkFrom=catalog) 中的[中文“自我介绍”](https://web-static.kurobbs.com/wiki_audio/1770098269166323983.wav)，原始录音为 10.624 秒、48 kHz、24-bit、单声道。默认参考现截到 4.20 秒，结束点位于 4.02–4.76 秒的停顿中；安装器保留完整原版为 `reference-original.wav`，短版仍使用 `reference.wav`。新版应用会在使用默认参考前本地升级与旧校验值完全匹配的长版，不下载文件、不更改其他自定义音频。使用时重采样为 16 kHz PCM16 WAV；每次参考 Base64 约 179 KB，比原版 453 KB 减少约 60%。可换成自己的清晰、单人 WAV；支持 PCM8/16/24/32 和 float32 WAV，MP3 请先自行转成 WAV。素材和角色权利归其权利人，分发、商业用途和声音复刻需自行确认授权，不能把公开可读取等同于版权授权。

官方接口说明：[MiMo ASR](https://mimo.mi.com/static/docs/quick-start/usage-guide/audio/Speech-Recognition.md)、[MiMo 语音合成](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/audio/speech-synthesis-v2.5)、[Eino ReAct](https://www.cloudwego.cn/docs/eino/core_modules/flow_integration_components/react_agent_manual/)。

## 7. Fish 双向流式与 reference_id

在桌面“设置 → 语音 → 语音合成”中将合成提供方切换为 **Fish**，填写 **Fish API Key** 和 **Fish reference_id**，保存后可用“试听语音”验证。默认根地址为 `https://api.fish.audio`、模型 `s2.1-pro`、延迟模式 `balanced`；可选 `normal`、`balanced`、`low`。API Key 使用密码输入框，保存方式与现有 MiMo/LLM 设置一致。

`reference_id` 优先于本地参考路径和参考文字。填写 ID 后不会读取/上传本地参考音频；未填写时，必须提供参考 WAV 和逐字对应的转写文字，二者在同一开始消息中发送。不自动创建、上传持久音色模型，也不会在 Fish 失败后自动切换 MiMo 或重放文本。

CLI 配置新增字段示例，其余 LLM/ASR 配置沿用原值：

```json
{
  "ttsProvider": "fish",
  "fishBaseURL": "https://api.fish.audio",
  "fishAPIKey": "填入你的 Fish API Key",
  "fishModel": "s2.1-pro",
  "fishReferenceID": "填入你的 reference_id",
  "fishLatency": "balanced"
}
```

环境变量覆盖支持 `AEMEATH_TTS_PROVIDER`、`FISH_API_KEY`、`FISH_BASE_URL`、`FISH_MODEL`、`FISH_REFERENCE_ID`、`FISH_REFERENCE_TEXT`、`FISH_LATENCY`。语音问题识别仍使用 MiMo ASR；Fish 的纯文字试听不要求 MiMo 密钥。

Fish 使用 `/v1/tts/live` WebSocket + MessagePack，同一会话持续发送 LLM 文字并同步接收 16kHz/16bit/单声道 PCM。文字不再经过 MiMo 的长句组分段器：完整短句或约 12～40 字的边界优先提交；没有合适边界时，待提交文字最多缓冲约 80 ms（不含下游背压），全文结束立即提交尾文。没有每轮 8 段限制，也不会在第 8 段等待全文。跨增量 UTF-8 与英文空白保留，整轮文字仍限制为 16 KiB；文字输入队列可容纳该预算内的全部非空增量，慢速合成不阻塞 LLM 正文更新。设备在首批 PCM 到达时开始未知长度播放；云端成功结束后才声明总采样数，实际 DMA 排空才确认播完。电脑缓冲为 2 秒 PCM 加有限消息队列，声卡信用不足会向 Fish 施加背压；取消同时终止 LLM、Fish 和待播音频。整轮总音频上限 120 秒，生成预算从首段文字开始为 180 秒，流式空闲等待上限 30 秒。需要广告 `stream_playback` 能力的新固件；旧固件会在云端请求前明确报错。

官方协议：[Fish WebSocket TTS](https://docs.fish.audio/api-reference/endpoint/websocket/tts-live)、[Fish 能力说明](https://docs.fish.audio/overview/capabilities)。真实账号权限、音色存在性及首音速度须在填写自己的 Key/ID 后验证；本地测试不调用付费云端。

## 8. 构建与诊断

macOS 语音版使用 [build-dmg.sh](../agent/scripts/build-dmg.sh)，自动暂存对应架构的 sherpa/ONNX Runtime 动态库，在签名前设置相对查找路径；可用 [verify-macos-voice.sh](../agent/scripts/verify-macos-voice.sh) 校验发布包。

```bash
bash agent/scripts/build-dmg.sh darwin/arm64 -o build/voice-validation
bash agent/scripts/verify-macos-voice.sh agent/build/voice-validation/darwin-arm64/Aemeath.app
```

Windows 监控版继续使用 [build-windows.sh](../agent/scripts/build-windows.sh)，不需要 cgo；语音版使用 [build-windows-voice.sh](../agent/scripts/build-windows-voice.sh)，额外要求目标架构的 MinGW-w64/llvm-mingw C 编译器与 NSIS，脚本会打包 DLL。构建成功与 Windows 实际硬件运行是两种不同验证。

```bash
CC=x86_64-w64-mingw32-gcc bash agent/scripts/build-windows-voice.sh windows/amd64
```

排障顺序：设备 `/ws` 连通 → `/voice` 握手 → 参考音频播放 → MiMo TTS 试听 → 模型就绪 → 唤醒 → ASR → Agent。声音小先检查桌面音量与设备静音；语音错误不会停止性能/额度采样。资源损坏先执行 `-verify`，再用新目录安装。

**局域网信任边界：**首版设备通道是明文 WebSocket，没有设备配对鉴权。仅在可信私有 LAN 使用，不要端口映射到公网；同网段其他程序可能占用语音通道或请求采集。需要跨网、多人环境或商用时，应先增加设备配对/令牌及加密传输。
