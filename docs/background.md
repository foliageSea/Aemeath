# 监控台自定义背景

## 使用

更新桌面应用与设备固件后，打开 **设置 → 屏幕 → 监控台背景**：

1. 点击“选择图片”，支持 JPEG、PNG、静态 WebP；原图不超过 20 MiB、3200 万像素，单边不超过 16384。JPEG 会先纠正 EXIF 拍摄方向，透明区域使用默认底色。不会修改所选原文件。
2. 在左侧方形预览中拖动图片，或使用水平/垂直位置滑块定位；缩放范围 1–4 倍，始终按 1:1 裁剪，最终输出 480×480，不拉伸原图。
3. 调整“图片亮度”和“对比度”（0–200%，100% 为原值）；这与上方的屏幕背光完全独立。“重置编辑”恢复居中裁剪、1 倍缩放、100% 亮度/对比度、质量 85，不删除设备背景。
4. “压缩质量”支持 40–95，默认 85。右侧是最终 JPEG 压缩预览，下方显示实际大小和质量。超过 192 KiB 时自动降低质量，最低为 40；仍超限则不能上传。小于 480 像素的裁剪区域会提示清晰度风险。
5. 点击 **上传并应用**。此操作独立于顶部“保存设置”；调整滑块只改变本地预览，不写设备、不反复擦写 Flash。未连接时可以离线编辑，连接后才能上传。上传使用当前连接的设备，而不是尚未保存的设备地址草稿。
6. “移除背景”确认后恢复纯色，重启后仍无背景；本地编辑草稿保留。

**默认没有背景图片**，底色为 `#0B0F14`；不再显示旧固件内嵌图片。背景是性能、订阅额度和语音三页共用的底图，卡片保持原有半透明样式，配网提示和二维码遮罩保持不透明。图片太亮会影响文字对比，建议适当降低图片亮度。

设备保存的是最终 JPEG，断开电脑、重启监控台后仍保留。本次应用会话中可继续从原图编辑；退出应用后原图和编辑工程不保存。“从设备载入”可将设备的最终 JPEG 作为新底图，有本地编辑时需要确认替换；原始构图或未裁剪部分需要重新选择原文件。

## 错误与恢复

- 图片格式/大小不合要求、内存不足、设备正忙等错误会显示提示，保留本地编辑。上传验证失败或提交前断线不替换原背景。
- 写请求不自动重试：设备可能已经保存，只是响应在网络中丢失。桌面端会尝试查询实际状态与摘要确认；无法查询时请重连后“刷新状态”，不要根据超时就认定设备未保存。
- 多个客户端修改时使用 revision 检查，不静默覆盖其他客户端的新背景。冲突后刷新状态，再决定是否应用本地草稿。
- 点击操作时同步绑定当前显示的设备连接；即使后台任务尚未开始就切换了设备，旧客户端也不能向新连接发送上传或删除。更换设备或断线后，旧结果不能更新新设备状态，不会在重连时自动上传本地草稿。
- 已保存但启动时无法解码/分配显示内存时，设备继续运行监控和语音，并报告“已保存但未能显示”；不会因此自动删除存储中的图片。
- 如果删除记录已保存但即时清屏失败，界面不会假称恢复纯色，会提示“显示未能清除”，并允许再次点击“移除背景”重试清屏，无需重复擦写删除记录。

## 固件升级与存储

背景需要 **固件和分区表一起更新**，仅更新 app 不能为旧分区表增加空间。使用网页刷机或发布 ZIP 中的分区烧录方式可保留原 NVS；不要为启用背景执行整片擦除。缺少分区时背景功能不可用，但原监控功能仍可使用。

[分区表](../firmware/partitions.csv)在原 6 MiB factory 分区之后追加 512 KiB background 分区：`0x610000–0x68FFFF`，原 NVS/PHY/app 的地址、大小不变。里面有两个 256 KiB 槽，分别写入图片或 EMPTY 删除记录：

- 先验证完整图片及解码结果，再擦写非当前槽；写入后读回校验，最后提交标记。
- 启动选择最新有效的已提交记录；提交前掉电保留旧记录，提交后使用新记录。
- 删除提交新的 EMPTY 记录，而不是只清内存或擦掉一个槽，因此重启不会恢复旧图片。
- 不将图片塞入 NVS，不把默认背景打包进新分区；相同图片或已经为空的重复操作不反复写 Flash。

整片擦除会清除背景。合并固件镜像会覆盖其覆盖范围内的间隙配置；保留配置时应使用发布 ZIP 的分区烧录方式。重新刷写应用和分区表但不擦除追加背景分区时，已上传背景可继续保留。

## 局域网 HTTP 契约（v1）

接口由[设备 HTTP 服务](../firmware/main/net/server.c)注册，桌面端通过[背景服务](../agent/internal/desktop/service_background.go)调用，不使用 WebSocket/base64，也不接触 Magpie 或云端服务。设备现有可信局域网模型不提供身份认证；不要将其 HTTP 端口暴露到公网，本功能也不开放 CORS。

| 请求 | 结果 |
|---|---|
| `GET /api/background` | JSON 元数据与 revision ETag |
| `GET /api/background/image` | 当前最终 JPEG；无图为 404 |
| `PUT /api/background` | 上传并持久应用，成功返回新元数据 |
| `DELETE /api/background` | 持久移除，成功返回新元数据 |

元数据字段：`v:1`、`supported`、`present`、`displayed`、`revision`、`sha256`、`width`、`height`、`bytes`、`maxBytes:196608`、`scope:"shared"`，可附 `error`。`present` 表示保存了图片，`displayed` 表示已在当前运行中显示；空背景尺寸与大小为 0、摘要为空。缺少背景存储时 `supported:false`。

修改请求必须携带 `If-Match: "<十进制 revision>"`；PUT 还需 `Content-Type: image/jpeg`、合法 Content-Length 和 `X-Content-SHA256`（正文 SHA-256 十六进制）。设备只接受 baseline 480×480 JPEG，正文不超过 196608 字节；桌面可读取 progressive JPEG/PNG/WebP 原图，但会重新编码成 baseline 后才上传。

典型错误：409 忙碌、412 revision 冲突、413 超限、415 类型不支持、422 内容/解码格式错误、503 资源不足。状态查询不会触发写盘。桌面端禁止跟随重定向，以免旧固件把未知接口跳转到配网页而误报成功。大图收发、JPEG 解码、Flash 操作通过有界异步 worker 处理，不在 HTTP 主循环长时间阻塞；Flash 操作仍可能影响实时性，必须在实际硬件上验证音频与监控。
